# Document center

Files kept against employees and business records, with versions, an access rule per document and no way to a
byte except the authenticated download.

---

## 1. Storage abstraction

`DocumentStorage` (`apps/api/src/modules/documents/storage.ts`): `put(key, stream) → {size, sha256}`,
`getStream(key)`, `exists`, `stat`, `delete`, `health`. One adapter ships: **`LocalFileDocumentStorage`**, a
directory on the API host, for development and pilot installations. Object storage (S3, Azure Blob, GCS) is a
future adapter behind the same interface.

Configuration: `DOCUMENTS_ENABLED` (default `true`), `DOCUMENT_STORAGE_DIR` (**required in production** while
enabled; refused if it is a temporary path such as `/tmp`), `DOCUMENT_MAX_FILE_MB` (default 20). Development and
test fall back to `apps/api/.data/documents[-test]`, which is git-ignored. The readiness probe reports
`documentStorage: ok | unavailable | disabled` and turns 503 when the root is not writable; `npm run ops:check`
prints it.

## 2. Path safety

A stored object's key is generated by the server — `documents/<2 hex>/<uuid>` — and is never derived from a title,
an employee or the uploaded file name. The adapter resolves a key to a path in exactly one place and refuses
anything that is not a generated key or that would leave the root: `..`, absolute paths, `%`-encoded traversal,
NUL bytes, drive letters. Tests exercise each case. The original file name is kept **for display only**, stripped
of control characters and directory parts, and sent back in a safe `Content-Disposition` (ASCII fallback plus
RFC 5987 UTF-8).

There is **no static file serving** (`express.static` is not mounted for uploads). The only route to bytes is
`GET /documents/:id/download`, which authenticates, authorizes, audits and then streams.

## 3. Upload security

Uploads are multipart (`file` plus metadata fields), streamed through busboy straight into the storage adapter with
the size limit enforced while streaming (an oversized file is cut off at the limit, not buffered) and the SHA-256
computed on the way. Before the object is kept:

- the extension must be one of `.pdf .docx .xlsx .png .jpg .jpeg .txt .csv` (a category may narrow this);
  `.exe .sh .js .html .svg .xml .bat .cmd .ps1 .php …` are refused whatever the declared type;
- the declared MIME type must not contradict the extension;
- the first bytes must carry the signature the extension promises (`%PDF`, PNG, JPEG, `PK` for Office files; text
  files must be NUL-free and must not start as HTML/SVG/XML or contain a script tag);
- the category's own size cap applies on top of the platform cap.

A refused upload leaves nothing behind. Inline preview (`?inline=1`) is honoured only for PDF, PNG/JPEG and plain
text, always with `X-Content-Type-Options: nosniff` and a sandboxing CSP; DOCX, XLSX, CSV and anything else are
always attachments. **No malware scanning is performed** — see §10.

## 4. Model

- **Category** (`document_categories`): code, name, `scopeType` (GENERAL, EMPLOYEE, HR, PAYROLL, RECRUITMENT,
  EMPLOYEE_RELATIONS, TRAINING, OTHER), default classification, optional extension allow-list and size cap.
  Customer-defined; nothing is inferred from a category's name. Dev fixtures: Employment contract, ID document,
  Certificate, Training certificate, HR letter, Payroll document.
- **Document** (`documents`): `DOC-YYYY-NNNNNN` (per-year counter under a row lock), title, description, category,
  optional owner employee and organization, classification, status ACTIVE/ARCHIVED, current version, issued and
  expiry dates.
- **Version** (`document_versions`): append-only — version number (unique per document), storage key, original
  file name, MIME, size, SHA-256, uploader, note. A replacement is version N+1 with its own object; bytes are
  never overwritten; old versions stay downloadable under the same authorization. Concurrent uploads take the
  document's row lock, so version numbers are unique and `currentVersionId` ends on the last committed one.
- **Link** (`document_links`): document ↔ (`entityType`, `entityId`) where the type is an enum (EMPLOYEE,
  TRAINING_ENROLLMENT, IDP, RECRUITMENT_CANDIDATE, RECRUITMENT_APPLICATION, EMPLOYEE_RELATION_CASE,
  DISCIPLINARY_ACTION). No table name ever comes from a request.

SHA-256 is stored for integrity and duplicate awareness; identical hashes are never merged automatically.

## 5. Authorization

Access to a document is the product of four things — permission, classification, the owning module's authority and
ownership:

| Classification | Owner (`documents.view_own`) | Manager (`documents.view`, TEAM scope) | HR (`documents.view`, ALL scope) | `documents.manage` |
|---|---|---|---|---|
| PUBLIC_INTERNAL | ✓ | ✓ for their team's owners | ✓ | ✓ |
| EMPLOYEE_PRIVATE | ✓ | ✗ | ✓ | ✓ |
| HR_CONFIDENTIAL | ✗ | ✗ | ✓ | ✓ |
| RESTRICTED | ✗ | ✗ | ✗ | ✓ (+ linked module) |

On top of that, a document filed under a PAYROLL, RECRUITMENT, EMPLOYEE_RELATIONS or TRAINING category, or linked to
one of those modules' records, **also** requires that module's permission (`payroll.manage`,
`recruitment.manage`, `employee_relations.view/manage`, `training.view/manage`, `idp.view/manage`). The owner is
exempted from the payroll and training requirement for their own EMPLOYEE_PRIVATE / PUBLIC_INTERNAL documents
(their own tax certificate, their own training certificate) but never from recruitment or employee relations, and
never for RESTRICTED. EXECUTIVE holds no document permission. Outside the caller's authorization a document
returns 404.

Linking a document to a record needs the record's module permission (`documents.manage` for an employee,
`training.manage`/`training.record_result` for an enrolment, `idp.manage`, `recruitment.manage`,
`employee_relations.manage`) and the record must exist. A link adds that module's authorization to the document;
it never changes who may see the record.

## 6. Archive and expiry

Archiving is a status: metadata and every version remain, the document leaves default lists (`status=ARCHIVED`
shows it), and no new versions are accepted. **There is no delete** after upload. Expiry is a date with a derived
state — VALID, EXPIRING_SOON (within 30 days), EXPIRED — computed on read; no scheduler, no reminder.

## 7. Audit

`CREATE_DOCUMENT_CATEGORY`, `UPDATE_DOCUMENT_CATEGORY`, `CREATE_DOCUMENT`, `UPLOAD_DOCUMENT_VERSION`,
`UPDATE_DOCUMENT_METADATA`, `LINK_DOCUMENT`, `UNLINK_DOCUMENT`, `ARCHIVE_DOCUMENT`, and `DOWNLOAD_DOCUMENT` for every
download of a non-public document (actor, document, version, classification, owner). Payloads carry ids, codes,
sizes and hashes — never file contents, descriptions or storage paths.

## 8. UI

HRM → Documents: **My documents** (the employee's own), **Document center** (search by title / number / employee,
filter by category, classification, status, expiry; upload with file policy shown; detail with current version,
history, hash, upload-new-version, links, archive), **Categories** (HR admin).

## 9. Backup and restore — read this before go-live

The PostgreSQL backup (`docs/operations-runbook.md`) covers **metadata only**. Once the document center is in use,
**`DOCUMENT_STORAGE_DIR` must be backed up separately** and restored together with the database: a database
restored without the matching storage yields documents whose objects are missing (the download answers
`DOCUMENT_OBJECT_MISSING`), and storage restored without the database yields orphaned files. Snapshot the storage
after the database dump of the same backup run and keep the pair together. `pg_dump` alone is no longer a complete
backup of this installation.

## 10. Known limitations

Local filesystem adapter only (no S3 / Azure / GCS yet); **no malware scanning** (place a scanner before or around
the upload in the deployment if required — the UI never claims files are scanned); no OCR or content search; no
e-signature; no approval workflow; no automatic retention or deletion; no external DMS integration; no
collaborative editing; no PDF generation; no scheduled expiry reminders; no bulk upload.
